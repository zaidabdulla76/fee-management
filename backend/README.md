# Backend API (`backend`)

FastAPI + SQLAlchemy + PostgreSQL service for the Hijri Fee Ledger.

Aligned with [`docs/fee-system-architecture.html`](../docs/fee-system-architecture.html).

## Stack

| Piece | Choice |
|-------|--------|
| Framework | FastAPI |
| ORM | SQLAlchemy 2.x |
| DB | PostgreSQL |
| Server | **gunicorn** + uvicorn workers (`entrypoint.py`) |
| Auth | JWT (Bearer) |
| Exports | WeasyPrint (PDF) + openpyxl (Excel), ReportLab fallback |
| Security | Runtime role `fee_app` — **Payment is INSERT-only** (NFR-1) |

## Layout

```
backend/
  app/
    api/routes.py       # HTTP surface
    core/               # config, DB, auth, Hijri helpers
    models/entities.py  # SQLAlchemy models
    services/           # billing, payments, late fee, reports, seed
  entrypoint.py         # bootstrap schema + grants, then gunicorn
  Dockerfile
  requirements.txt
  .env.example
```

## Run with Docker (recommended)

From the repo root:

```bash
docker compose up --build
```

The `api` service is **not** published on the host. Reach it through Nginx at `https://localhost/api/...`.

On start, `entrypoint.py`:

1. Connects as DB owner (`fee`) via `DATABASE_URL_ADMIN`
2. Creates tables + seeds admin / fee types / Hijri months
3. Applies grants so `fee_app` cannot UPDATE/DELETE `payments`
4. Starts gunicorn with `DATABASE_URL` = `fee_app`

## Local development

### 1. Infra (Postgres)

From the **repo root** (`d:\fee`), not `infra/`:

```bash
docker compose up -d postgres
```

That starts Postgres from `infra/postgres/init` on **localhost:5433**
(host port **5433** so it does not clash with a Windows PostgreSQL on 5432).

Full stack (API + web + nginx + scheduler + postgres):

```bash
docker compose up --build -d
```

Then open https://localhost

### 2. Install & run API on the host

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

For quick local reload (owner role). If the DB was never bootstrapped, start the Docker `api` once first (`docker compose up -d api`) so tables/admin exist:

```bash
set DATABASE_URL=postgresql+psycopg://fee:fee@127.0.0.1:5433/fee
uvicorn app.main:app --reload --port 8000
```

API docs: http://localhost:8000/docs  
Health: http://localhost:8000/api/health

Default admin (seeded): `admin` / `admin123`

### 3. Production-like local process

```bash
set DATABASE_URL_ADMIN=postgresql+psycopg://fee:fee@localhost:5432/fee
set DATABASE_URL=postgresql+psycopg://fee_app:fee_app@localhost:5432/fee
set JWT_SECRET=fee-mgmt-dev-secret-change-me
set INTERNAL_SWEEP_TOKEN=fee-internal-sweep-token
python entrypoint.py
```

## Environment

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | Runtime DB URL (`fee_app` in Docker; derived on Render if omitted) |
| `DATABASE_URL_ADMIN` | Owner URL used only during bootstrap |
| `FEE_APP_PASSWORD` | Password for the `fee_app` role (default `fee_app`) |
| `JWT_SECRET` | JWT signing key |
| `INTERNAL_SWEEP_TOKEN` | Bearer token for `POST /api/internal/late-fee-sweep` |
| `CORS_ORIGINS` | Comma-separated origins, or `*` |
| `WEB_CONCURRENCY` | Gunicorn workers (default `2`; use `1` on small PaaS instances) |
| `PORT` | HTTP bind port (default `8000`; Render sets this) |
| `GUNICORN_TIMEOUT` | Worker timeout seconds (default `120`, for PDF exports) |

## Deploy (Render)

The repo-root [`render.yaml`](../render.yaml) Blueprint creates:

1. Private Postgres 16 (`fee` / owner `fee`, no public IP)
2. Docker web service from `backend/Dockerfile` (`hijri-fee-api`)
3. Cron at **00:15 UTC** that POSTs `/api/internal/late-fee-sweep` once and exits

Secrets (`JWT_SECRET`, `INTERNAL_SWEEP_TOKEN`, `FEE_APP_PASSWORD`) are generated by Render — do not put them in git.

1. Push this repo to GitHub.
2. Render Dashboard → **New** → **Blueprint** → select the repo.
3. After the API is live, set Netlify’s `/api/*` proxy to that URL (see root README) and optionally lock `CORS_ORIGINS` to your Netlify origin.

The UI is **not** on Render. Netlify serves the SPA and proxies `/api` same-origin (same pattern as local Vite and Docker Nginx).

## Main endpoints

| Method | Path | Notes |
|--------|------|-------|
| POST | `/api/auth/login` | Issues JWT |
| GET/POST | `/api/students` | List/search, create |
| POST | `/api/academic-years/{id}/enroll` | Generate 12 Tuition bills |
| GET | `/api/students/{id}/years/{ay}/tuition` | 12-month grid |
| POST | `/api/bills/{id}/pay` | Mark Tuition paid |
| GET | `/api/fee-types/{id}/items` | FR-12 variants |
| POST | `/api/collections` | Atomic non-Tuition bill+payment |
| GET/PUT | `/api/settings/*` | Fees, late-fee rule, classes |
| GET | `/api/reports/*` | JSON / `?format=pdf\|xlsx` |
| POST | `/api/internal/late-fee-sweep` | Scheduler only |

## Academic years (FR-3.4)

- Period is always **Shawwal → Ramadan** (12 × 30-day billing labels).
- After the first year, the next Shawwal start is **exactly** one year length (360 days) after the prior Shawwal start — i.e. the day after prior Ramadan ends.
- `GET /api/academic-years/next-start` returns the required date for the UI.

## Data integrity (NFR-1)

- Payment rows are **append-only** at the ORM layer (update/delete blocked) as well as via Docker `fee_app` grants.
- Tuition bill identity fields are immutable after create; only `status` and `late_fee_amount` may change (late-fee sweep / mark Paid).
